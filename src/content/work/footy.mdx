## Overview

[**Footy**](https://farcaster.xyz/miniapps/vRlFDfogkgrw/footy-app) is a football-focused mini-app on Farcaster, built to be the ultimate hub for everything football related. Its flagship feature, **Score Square**, is a matchday betting game where users buy squares representing potential final scores. The buyer of the winning square — matching the game's actual final score — wins the entire prize pool collected from ticket sales.

Beyond Score Square, Footy keeps fans connected with their teams through notifications when their teams are playing, live match chats, community discussions, and real-time updates, making it the go-to destination for football lovers.

## Project Objective

The Footy mini-app was built by [**KMac**](https://farcaster.xyz/kmacb.eth) with a focus on functionality over visual polish, but the app had gotten to the point where it was functional enough and needed some visual love. There were also some user experience pain points that needed ironing out to make using the app a smoother and better experience.

My goal was to overhaul the visual language of the Footy mini-app to create a more engaging and visually pleasing user experience. Alongside the redesign, I also wanted to develop a comprehensive design system to ensure every part of the app consistently reflects the new visual identity and supports future scalability and feature development.

## The Process

I chose to redesign the Score Square feature first as it is Footy's most-used and most impactful product. Redesigning the Footy core experience (Score Square), the redesign promised the highest and most immediate returns in terms of usability, engagement, and overall design improvement.

Score Square has only two screens. Screen 1 is the screen showing all live games at any given time.

Screens 2–4 are all the same screen in different states. When you select any game you get taken to a screen with more details about the game and an interface to allow you purchase "squares" and buy in to the game. That process updates the screen numerous times from square selection to the successful purchase of one or several squares.

![The Score Square screens as they were before the redesign](/work/footy/before-score-square.webp)

The second screen required particular attention because of all the state changes that occur. In addition to the state changes, it's also a text-heavy interface where a significant amount of context must be presented to help users make informed decisions. However, presenting too much information at once risks overwhelming the user, leading to them abandoning the process.

My redesign focused on two key objectives:

1. **Streamlining content** to ensure only the most relevant information is displayed at each step.
2. **Elevating the visual identity** to create a cleaner, more intuitive experience that supports decision-making without cognitive overload.

## Act 1: Streamlining Content

Score Square is information-heavy, so managing screen real estate effectively is crucial to helping users navigate easily and have a smooth experience.

To address this, I began by establishing a clear hierarchy of content based on priority — focusing on what users need to see to achieve their goal of buying into a game. I also kept [Miller's Law](https://lawsofux.com/millers-law/) in mind, aiming to reduce cognitive load by limiting how much information appears on each screen.

Here are some changes I made at the end of this process:

1. I moved instructions into a modal instead of displaying them on the screen along with everything else when the user clicks on "show instructions". This helped to declutter the interface and keep the main flow free of unnecessary distractions.
2. I moved the final payout details into the instruction modal as well. While transparency about why the winner doesn't receive the full pot is important, that information isn't essential when a user is focused on buying a square. Moving it into the modal helped declutter the main page, and users still see a full breakdown of their winnings when they win — maintaining transparency without sacrificing clarity.
3. Initially, state changes were split between the squares frame and an area above it, which fragmented the user experience. To improve clarity, I updated the design so that all state changes occur within the frame. This not only creates a more cohesive visual experience but also matches the user's mental model of "looking at the square" to understand what is happening while they wait for their transaction to be completed. An example is shown below: when the user taps "buy squares", one of the states shown is "transaction submitted, waiting for confirmation" — but there has been a change in how this information is displayed in the redesign.

Finally, I removed information that didn't support the user's immediate goal. For instance, the "date deployed" detail adds no real value when all the user is trying to do is buy into a game, so removing it helped maintain focus and reduce cognitive load.

Having dealt with the information hierarchy problem, I turned my attention to the visual identity.

## Act 2: Elevating Visual Identity

I focused on two things predominantly while redesigning the visual identity: colours and typography. Of course I also worked on things like spacing and iconography — however, the colours and typeface used (as well as how they are used) are foundational elements to any good design system.

### Colours

The first step in the redesign was refreshing the colour palette by simplifying it. I reduced the system to three core colours, using their variations to communicate state changes and act as visual signifiers. Muted tones helped deprioritise supporting elements, while stronger accents directed attention to key actions and information. Using these three core colours I created colour styles for UI elements like buttons, surfaces, text, borders, and so on. I focused on simplicity, coherence, and covering the full range of necessary interaction states (active, disabled, etc.) for interactive elements.

### Typography

After refining the colour palette, I turned my attention to typography — aiming for clarity and consistency rather than expressiveness.

It's common practice in design to use at least two typefaces for a project — a serif typeface and a complementary sans-serif typeface.

However, Score Square is a content-heavy page with minimal headers and largely uniform text. Because most of the content serves an informational role, I chose a single typeface with strong readability and flexible weights to maintain consistency and make it easier for users to scan and locate specific information. I chose Josefin Sans for its legibility at small sizes, its modern feel, and a wide weight range, and then I paired that with colour styles to convey visual hierarchy.

## Act 4: Some UX Extras

Although I started the process of redesigning the entire app by focusing on a visual redesign of Score Square, talking to users has led to several UX tweaks in the meantime.

For example, the first page a user saw when they opened the app used to be a generic **Matches** page that showed the next round of English Premier League games. Once we started enabling users to set their favourite teams and receive notifications for them, we realised that the first screen users see needs to be more personalised. Now we show users a **For You** page that shows games for the teams they select, no matter the league.
