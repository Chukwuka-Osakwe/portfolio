## Overview

Aronia is a component library I'm building for a world where the thing consuming
your components is often an agent, not a person clicking through Storybook. You
set it up with a single command — `npx aronia init` — then pull in components as
you need them (`aronia add button`), each landing in your project with a
machine-readable manifest so an agent can discover what exists, what it takes,
and how to drop it in.

The gallery on the left is the human-facing half: pick a component, watch it
render live in the middle, and drive every prop from the panel on the right —
`variant`, `size`, `state`, `shape` — with the preview updating as you go. Under
the hood the components lean on native platform primitives (`<details>` for
disclosure, the `popover` attribute and CSS Anchor Positioning for menus) so
accessibility and behaviour come for free instead of being re-implemented in
JavaScript.

It's the piece of the lab that pushes furthest past design into
engineering — CLI tooling, an agent-oriented API, and a design system that has
to hold up under both human and machine use.

To get started with Aronia today just run `npx aronia init` — or paste the
GitHub link into the chat with your agent and tell it you want to use the Aronia
library for your project. Have fun!
