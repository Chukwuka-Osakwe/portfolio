# Design Decisions

Project-wide design decisions for the portfolio. This documents *what* we decided and *why*, so choices stay consistent across sessions. Update it whenever a decision is made or changed.

---

## Stack & Architecture
- **Next.js 16 (App Router) + React 19 + TypeScript.** Deploy target is Vercel.
- **Static-first.** Every route is prerendered (static or SSG via `generateStaticParams`). No runtime data fetching for now. `dynamicParams = false` so unknown slugs 404 at build time.
- **Views are real routes (2026-05-27).** Under an `app/(site)/` route group sharing one chrome layout (nav/hero panel + fixed bottom switcher): `/` (projects), `/contact`, `/product-ideas`. Each prerenders its own view, so refresh/deep-link lands on the right view with **no client-side flash** — the active view *is* the pathname (`usePathname`), not React state. (Replaced the earlier single-page `ViewContext.active` model; that flashed the default view on refresh because one static HTML served every view.) `ViewContext` now only holds small cross-tree UI state (`detail` — the open project slug). The project **detail** still opens in-place on `/` via the `#slug` hash. *(`node` — the hovered/focused card coordinate — was removed 2026-06-02 alongside the Matrix readout.)*
- **Tailwind CSS v4.** Config lives in CSS (`@theme` in `globals.css`), not a `tailwind.config.js`. Plugins are loaded via `@plugin` in CSS.
- **Build note:** `next build` uses Turbopack by default in v16, regardless of the dev `--no-turbopack` flag.

## Content Pipeline (Writing)
- **MDX via `next-mdx-remote/rsc`** (chosen over `@next/mdx` page files) so we get a *content collection*: list pages by reading the filesystem, with frontmatter.
- Content lives in `src/content/{work,writing}/*.mdx`. One file = one entry.
- **Product ideas = typed data, not MDX (2026-05-27).** An idea is just a cover image + a one-line caption (no body), so the set is a typed `Idea[]` in **`src/content/ideas.ts`** (with `getIdeas()`), sitting beside the MDX sections rather than being a third MDX section. Fields mirror `Frontmatter` (`image`, `width`/`height`, `blurDataURL`, `caption`, `draft`) so promotion to MDX would be mechanical — the file header documents that path, and `lib/content.ts`'s `Section` type carries a pointer comment explaining why ideas isn't a `Section`.
- **Frontmatter** parsed with `gray-matter` (`src/lib/content.ts`): `title`, `summary`, `blurb`, `date` (ISO), optional **`type`** (work — e.g. `"PRODUCT DESIGN"`, `"VISUAL DESIGN"`), **`image`** (card cover, path under `/public`, e.g. `/work/footy/cover.png`), `draft`, `featured`. *(`tags` was declared but never rendered — deleted 2026-06-02 with the orphan `EntryList` component, its only consumer. `role` was `type`'s predecessor — still in the type for back-compat, but no case study uses it; safe to remove.)*
- **`type` label (2026-06-02, restyled 2026-06-04):** an optional category label (`"PRODUCT DESIGN"`, `"VISUAL DESIGN"`). Same typographic language in both contexts — uppercase, `text-xs` (12px), `font-semibold`, `tracking-wider`, `text-text-muted` — but **position and shape differ by surface**:
  - **Card:** rendered as an **eyebrow ABOVE the title** (editorial pattern), no chip background. The card itself is the button-shaped surface; a chip on top was double-buttoning.
  - **Detail header:** rendered **below the H1** as plain `inline-block` text (still no chip) — the position is reserved for a future **action-pill row** (e.g. a "view live →" CTA) to sit alongside, where the visual distinction between plain-text label and chip-shaped CTA carries function (label = metadata, chip = clickable).

  Takes precedence over `role` (legacy) in the renderer; if both unset, the slot is empty. *(The original 2026-06-02 chip styling — `bg-accent-fill rounded-md px-2 py-1 self-start text-text-muted` — was retired 2026-06-04: read as "muted on muted," double-buttoned the card, and committed the slot's shape before there was a chip-shaped sibling to differentiate from.)*
- **Card blurb = `blurb`; `summary` = SEO (2026-05-24).** Two separate fields: **`blurb`** is the card preview text (clamped to 3 lines; bumped from 2 on 2026-06-02 to fit ~130-char hooks), falling back to `makeExcerpt(body)` (first sentences of the body) only when a file omits it. **`summary`** is kept distinct and reserved for the eventual SEO / OG meta description — it does *not* drive the card. (Authored blurb beats auto-extraction.)
- **Card cover (`image:`, wired 2026-05-23):** rendered via `next/image` (`fill`/`object-cover`) in an **`aspect-[31/20]`** (1.55:1) card header — height scales with card width. Falls back to a **`bg-image-placeholder`** block (a field-tracking shade — see Color) when unset. **Cover art direction is prescriptive: export at 1.55:1** (e.g. 8000×5172 → 1600×1034 derivative). Other aspects render OK but get center-cropped by `object-cover`. *(History: 2026-05-23 fixed 200px height; 2026-06-02 tokenized to `--card-cover-h: 12.5rem`; 2026-06-03 switched to aspect-ratio so the slot fits the established 1.55:1 brand-board export format without horizontal crop. The `--card-cover-h` token is gone.)*
- **Body images (`![]()`):** mapped in `mdx-components.tsx` to a styled **native `<img>`** (`my-8 w-full border border-border`, `loading="lazy"`, square corners) — *not* `next/image`, because MDX images have arbitrary unknown dimensions. Since these are raw `<img>`, **the format shipped is the format downloaded** (no on-the-fly conversion) — so the WebP/sizing decisions below matter most here.
- **`<Figure>` (centered, width-capped image; added 2026-05-23):** a custom MDX component for shots that shouldn't run the full column width. `<Figure src alt width="69%" />` — `width` is any CSS length/% (default `66%`), always centered (`mx-auto`), capped to the column (`maxWidth:100%`), same border/lazy as `img`. Use plain markdown `![]()` for full-width (default); reach for `<Figure>` to inset. **Because all body images render at the column width, on-screen *height* is governed by aspect ratio** — to match two images' heights, match their aspect ratios (or cap the squarer one's width: a 1:1 image at `width = 1/AR` of a landscape image renders the same height). The Act 2 colours (square) + typography (1.45:1) are a centered pair, both `width="69%"`.
  - **`caption` / `captionBefore` / `captionAfter` props (2026-05-26, two-line variant added 2026-06-03):** when any is set, the component renders `<figure><img><figcaption></figure>` and owns the 8px image↔caption gap internally (replaces the old `*italic*` markdown-paragraph caption pattern, which suffered margin-collapse with the wrapper). Use **`caption`** for a single-line caption; **`captionBefore` + `captionAfter`** for a two-line stack (e.g. a composite "before / after" Figure — mirrors `<Compare>`). Same pattern available on `<Screens>` and `<Compare>`. **MDX gotcha:** `next-mdx-remote/rsc` silently drops JSX-expression props — use string props (`captionBefore="…"`), not `caption={<>…</>}` (the JSX form falls back to `undefined`; see [[mdx-jsx-expression-props-dropped]]).
  - **Caption system — CSS architecture (`.case-body figure`, unified 2026-05-26).** The `<figure>/<figcaption>` path is now the **single truth** for case-study captions; the old `*italic*` paragraph-after-image pattern (and its `:has(+ p:has(> em:only-child))` sibling-selector workaround) is retired. The CSS in `.case-body`:
    - **`figure { margin-block: 2rem }`** — outer 32px breathing room stays on the figure, not the media inside.
    - **`figure > img | div | picture { margin-block: 0 }`** — internal media has zero block margin (gap is owned by the figcaption below it).
    - **`figure img { margin-block: 0 }`** (scoped to `margin-block`, **not** `margin: 0`) — defeats `.prose img { margin: 2em 0 }` for *deeply-nested* imgs (e.g. inside `<Compare>`'s flex-cell wrappers), which otherwise leave a phantom strip above. Using the shorthand `margin: 0` would trample `margin-inline: auto` and left-align Figure's centered imgs (burned an hour on this).
    - **`figure > figcaption`** — `margin-top: 0.5rem` (8px gap), capped to **`--caption-measure` (36rem)**, `margin-inline: auto` (centered), `text-align: center`, `text-sm` / `leading-[1.3]`, `text-text-muted`. **Upright** (italics dropped — figcaption is its own type role, not emphasis).
    - **`figure > figcaption > p { margin: 0 }`** — when the figcaption holds two `<p>` lines (`captionBefore` + `captionAfter`), they stack tight (no prose 1.25em paragraph margin between them), reading as one block.
    - **Why a system, not per-component CSS:** Figure / Screens / Compare all render the same `<figure>/<figcaption>` shape, so one rule set covers all three; component code just decides what goes *inside*. (Markdown-image captions in the only-remaining placeholder still flow through `.case-body > p:has(img) + p` until that file is culled.)

### Image workflow — masters & derivatives (convention, 2026-05-23)
**Two-tier model. Never edit-over or ship a master; always regenerate derivatives from it.**
- **Masters** = full-res, *lossless* originals (PNG / the original drop). Live in **`/sources/<...mirror of /public path>`** (e.g. `sources/work/footy/colours.png`), **gitignored** (heavy, not deployed). When the user drops a raw file in the project root, **`mv` it into `/sources`** — *never* `rm` it (deleting masters = losing the ability to re-crop/resize; this bit us once — the 4 hand-dropped Footy images were deleted before the convention existed and need re-dropping).
- **Derivatives** = downscaled, web-format copies in **`/public/work/<slug>/`**, regenerated from the master via `sharp`. These are what the MDX references and what ships.
- **Sizing (the dominant size lever, ~free quality-wise):** resize so the longest edge ≤ **1600px** for landscape/full-width shots, or to **~2× the on-screen display width** for anything inset/gridded (e.g. the 2-up phone screens render ~352px → re-cut at **740px wide**). Most of the savings is right-sizing, not compression.
- **Format / compression (per image *type*):**
  - **Flat UI / screenshots / text** (palettes, component sheets, specs): **near-lossless** WebP (`{nearLossless:true, quality:80, effort:6}`) or lossless — pixel-clean text, and still tiny (these compress so well that even lossless often beats the PNG master).
  - **Photographic** (photos, mockups, moodboards): **lossy** WebP `quality:80–85` — lossless would balloon these.
  - WebP is universal in 2026; AVIF is an option for even smaller photographic files (slower encode). `effort:6` is a free quality-per-byte win.
- **Result so far:** the Footy set went **10 MB → ~0.7 MB (−93%)** at q80; UI shots later re-encoded near-lossless cost only a few dozen KB more each.
- **Real case studies** authored from a Notion export. The raw export lives in `/the-notion` (gitignored — heavy, has videos); curated + renamed masters live in `/sources/work/<slug>/`, derivatives in `/public/work/<slug>/`. Convert: demote Notion `#` headers to `##`, drop the leading title (the detail-view header shows it), strip videos (v1 decision: no video), keep image captions as `*italic*` lines.
- **Idea covers (2026-05-27):** same masters (`/sources/ideas/`) → derivatives (`/public/ideas/`) model. Each `Idea` carries a base64 **`blurDataURL`** (a tiny `sharp` LQIP) for `next/image` `placeholder="blur"`, plus intrinsic `width`/`height`. `scripts/cover-4x3.mjs` turns any source into a 4:3 **blurred-fill** (full image centered over a blurred copy of itself — fills the frame with no crop or letterbox) — though the launch covers were ultimately re-exported at a uniform **~1.55:1 (2000×1293)** instead. **Cache-bust gotcha:** swapping a cover at the *same* `/public` path serves a stale result (the browser **and** `.next/cache/images` key on the URL, not the bytes) — rename to a fresh filename (we version `-v2/-v3/…`) whenever a cover's content changes.
- **Idea carousel is a single non-scrolling page:** the cover is **height-capped** (`lg:max-h-[calc(100dvh-22rem)]`, `w-auto`) so on short viewports it scales *down* (staying centered, no crop/letterbox — the frame equals the image) instead of forcing the page to scroll. The `22rem` is the reserved budget for header + counter + caption + gaps.
- `draft: true` hides from listings; `featured: true` is reserved for a homepage rail. Lists sort newest-first by `date`.
- MDX plugins: `remark-gfm` (tables, etc.) + `rehype-slug` (heading anchors). Add `rehype-pretty-code` later if code samples need highlighting.
- Custom MDX element overrides in `src/components/mdx-components.tsx` (e.g. internal links routed through `next/link`).
- **Watch for ("where MDX breaks"):** a malformed expression or bad import inside any `.mdx` fails the whole build; frontmatter typos surface as missing fields, not errors.

## Responsiveness
- **Mobile-first.** Style the base (smallest) case unprefixed, then add `sm:`/`lg:` to scale *up*. Targets every device from phone to large desktop.
- **Fluid sizing (preferred while iterating):** size type *and* spacing with `clamp(min, vw, max)` so one value scales smoothly across all screens — no `sm:`/`lg:` variants to maintain or accidentally wipe when tweaking an element. e.g. heading `text-[clamp(1.25rem,4vw,1.5rem)]`, section `py-[clamp(3rem,8vw,5rem)]`. Keep `text-balance` on headings, `text-pretty` on leads. Values are rem-based so user zoom is respected. Adjusting size = nudge the `max` (one number).
- **Breakpoints** (Tailwind defaults — `sm 640 · md 768 · lg 1024 · xl 1280`) are reserved for true *layout* changes (column count, show/hide, grid → stack), **not** type/spacing scaling. See [[responsive-iteration-style]].
- **Overflow guards (convention):** flex children holding text get `min-w-0`; long unbroken strings get `break-words`.
- **Full-height (when needed):** use `min-h-dvh`, not `vh`/`min-h-screen`, to account for mobile browser chrome.
- **Deferred until content exists:** `next/image` with `sizes` + aspect ratios; ≥44px touch targets for interactive elements; `prefers-reduced-motion` guards for any animation.

## Layout & Structure
- **Single page** (`/`), **two-column on desktop — viewspace + navbar (decided 2026-05-26; replaced the 3-track gutter model):** a **full-width** CSS grid — `lg:grid-cols-[minmax(0,1fr)_var(--nav-w)]` (mobile: `grid-cols-1`, `px-6`, `gap-y-12`; desktop: `lg:px-0`, `gap-x-8` = 32px column gap, `lg:min-h-dvh`).
  - **Track 1 (`minmax(0,1fr)`) = the viewspace** — fills all width that isn't the navbar. Its content (cards / carousel / detail) is capped to **`--content-w` (49rem)** and **centered** (`mx-auto`), so the cards stay a constant readable width at every screen size and surplus width becomes balanced margin, not oversized cards. **This retired the parked wide-screen debt** (the old model let the cards flex-grow indefinitely).
  - **Track 2 (`var(--nav-w)`, 21rem) = the identity / nav panel** — fixed, dial-able width. As the *last* track of an edge-to-edge grid, its `bg-nav-fill` (white) **bleeds to the right viewport edge on its own**.
  - **Placement:** cards `<section>` `lg:col-start-1 lg:row-start-1`; panel `<aside>` `lg:col-start-2 lg:row-start-1`. The aside is **first in DOM** so it stacks on top on mobile (pin both to `lg:row-start-1` or the DOM-first aside pushes cards to row 2).
  - **Centered ≠ viewport-centered:** the cards center within the *viewspace* (viewport minus navbar), so the block sits slightly left of true page center — which counterbalances the navbar's weight on the right.
  - **Panel full-height:** `lg:min-h-dvh` on the grid + `lg:-mt-8 lg:-mb-24` on the aside (cancel the grid's `pt-8`/`pb-24`) so the white reaches the top & bottom screen edges.
  - **Scrollbars hidden site-wide (2026-05-26):** `* { scrollbar-width: none }` + `*::-webkit-scrollbar { display:none }` (scrolling still works). This was the settled answer to "the scrollbar sits on the navbar" — chosen over a fixed-navbar/scrolling-viewspace split (tried, reverted) and a recolored gutter. `scrollbar-gutter` dropped; `html { background: var(--background) }` (overscroll color).
  - **History:** this replaced the 2026-05-23 three-track model (`[1fr · minmax(0,49rem) · minmax(24rem,1fr)]` with a left-margin gutter track), which itself replaced a fixed-`18rem` + faked-`::after`-bleed model. Each step removed magic numbers; the 2-col + centered-cap is the simplest and fixes wide screens.
  - **Nav content wrapper:** the panel's content lives in an inner **`lg:sticky lg:top-8`** wrapper, **capped `lg:max-w-[28rem]`, `lg:mx-auto`** (centered in the panel), with **`lg:px-8`** (32px) gutters. The cap engages only once the panel exceeds cap+gutters; below that the content stays 32px off both edges. (Earlier the content was uncapped 32px-off-edges and got too wide on big screens.) Order top→bottom: logo row → hero text → accent rule → menu → accent rule → **(viewport tail)** → theme toggle. The toggle is **centered in the remaining tail** below the menu, not glued 48px under the lower accent rule — on `lg`, the sticky wrapper is `flex h-[calc(100dvh-2rem)] flex-col`, the upper block (logo+hero+menu) sits at natural height, and a `flex-1 items-center justify-center` lower block fills the remaining viewport height and centers the toggle in it. Mobile keeps natural `mt-12` stacking (mobile re-jig deferred). **Concession:** on very short viewports where the upper content grows tall, the lower block can be crushed — current content has headroom; revisit if menu/hero balloons.
  - **Hero text:** heading + subhead **merged into one left-aligned `<h1>`**, `text-sm` (14px), `lowercase` (CSS — source keeps real caps), `text-pretty`. Copy: "hello, i'm chukwuka, a systems-oriented **designer** … (sometimes)." ("designer" in `text-accent`.)
  - **Accent rules:** two **4px** lines (`h-1 bg-accent`) bracket the menu (one above, one below). They span the **full panel width** via `lg:-mx-8` (cancel the content `px-8`) while items stay inset 32px. (Replaced the old vertical divider + the two `border-accent` bracketing rules.)
  - **Matrix readout (retired 2026-06-02):** *Was* a mono coordinate gag `matrix node [row,col]` reflecting the hovered/focused card (idle `[–,–]`; coord in accent), wired via `node`/`setNode` on `ViewContext` + per-card hover/focus handlers. Removed in S9 — component, context fields, and the `COLS = 2` constant all deleted. The "chukwuka's matrix" brand name stays (it's the logo, unrelated). The tail slot is now the **theme toggle**. *(Earlier-removed: a mono "system readout" — status/location/live Lagos time. Showing the visitor's location/local time was discussed — timezone-client vs Vercel-edge vs IP-API — and **deferred** (privacy + static-build tradeoffs).)*
  - **Below `lg`** the grid collapses to one column: identity panel on top (full-width, no bleed), cards below.
  - **Why right-side nav:** chosen look; unconventional (nav usually top/left) and the split necessarily stacks on mobile.
- **Card-column routing (decided 2026-05-22):** the cards column is a swappable content area driven by **one shared piece of state** — `active: ViewId` in a **`ViewProvider` context** (`useView`). `ViewId = "projects" | "product-ideas" | "contact"`. Two controls set it (they live in different parts of the tree, hence the context):
  - **`NavMenu`** (client, the "things i do:" list in the identity column) = **top-level routes**. Each item is a `view` (in-app route → `setActive`) or an `href` (external, new tab). *design* → `projects` (in-app); *contact* → `contact` (in-app); *essays* → `https://thechukwukaosakwe.wordpress.com/`; *newsletter* → `https://chukwukaosakwe.substack.com/`. (NavMenu still supports an inert third state for any item with neither.)

(bg lives in the `INACTIVE`/`ACTIVE` state constants, not the base class, to avoid a Tailwind `bg-*` conflict between inactive white and active accent-fill.)
  - **`ViewSwitcher`** (client) = a **sub-toggle within the design area only** (projects ↔ product-ideas). Fixed, frosted segmented control docked bottom-center of the cards column (`fixed inset-x-0 bottom-6`, mirroring the page grid; `pointer-events-none` wrapper, only the pill interactive). `rounded-lg` track, two equal `grid-cols-2` segments, an absolutely-positioned **sliding thumb** (`bg-switcher-thumb` — its own stronger fill, *not* `--accent-fill`; `rounded-md`, `translateX(activeIndex*100%)`, `motion-safe`). **Both segment labels are the same** (`text-foreground`, same weight) — the thumb is the *sole* active indicator (backed by `aria-pressed`). **Renders `null`** when `active` isn't one of its two segments (e.g. contact) **or while a project detail is open** (the cards aren't rendered then — see `detail` in `ViewContext`).

  - **Essays sourcing — deferred (discussed 2026-05-22).** Currently *essays* is just an external `href` to the WordPress site. We discussed bringing essays *into* the viewspace as an `essays` route, and what native publishing would cost. Findings:

React 18 tolerated this silently; React 19 / Next 16 surface it as a hydration mismatch. The div + `onClick` + `onKeyDown` (Enter / Space) replicates button behaviour; `focus-ring` utility carries the keyboard outline. Ref type is `HTMLDivElement`.
  - **In-place detail:** rendered in `ProjectsExplorer` — a "← back to work" control + `<article>` at the **`--reading-measure` (42rem) cap** (`mx-auto`), header with **`<h1>` title** + type pill (`border-b-4 border-accent` rule, **bumped from `border-b-2` on 2026-06-03** to match the navbar's two `h-1` accent rules — both now read as the same 4px line), then the `.case-body prose`. Title is `<h1>` because the case-study title *is* the page's primary heading (semantic fix 2026-06-03; was an `<h2>`); body sections stay `<h2>`/`<h3>`. **Esc** and "back" return to the grid (restoring focus to the source card). Enter motion = **`.view-enter`** (fade + 8px rise, reduced-motion-safe). No shared-element/grow animation.
  - **Why it replaced the modal (which we'd built + polished):** the in-place pattern reuses the existing viewspace-swap model (it's just another thing the column shows), gives a tighter **44rem** reading measure (vs. the modal's wide panel), keeps the navbar live (no backdrop/scroll-lock), and unifies "open a project" with the other view switches. The whole `<dialog>` + WAAPI container-transform + scroll-lock + `::backdrop` apparatus was deleted.
  - **State + deep-linking:** the open slug lives in **`ViewContext` (`detail`)** so the ViewSwitcher can hide while it's open; mirrored to the URL hash (**`/#slug`**) for shareable, back/forward-able links (load + `popstate`/`hashchange` drive it). Hash deep-links, not per-project routes.
  - **Reload on `/#slug` — pre-paint mask + `useLayoutEffect` (2026-06-03 flash-fix):** SSR can't see `location.hash` (browsers strip `#` server-side), so a cold reload on `/#bribe` would SSR the grid, paint it, then `useEffect` would swap to detail post-hydration — visible flash. **Fix:** an inline `<head>` script sets `html[data-detail-pending]` synchronously if a hash is present; CSS `.project-grid { visibility: hidden }` masks the grid through the JS-load window (visibility — not display — keeps layout stable). `ProjectsExplorer`'s initial hash read moved from `useEffect` → **`useLayoutEffect`** so the detail commits synchronously before paint, and the same effect clears `data-detail-pending`. Subsequent hash changes stay in regular `useEffect`. **General pattern:** server-unknown state (localStorage, `location.hash`) either defers to post-paint (and flashes) OR is resolved by a pre-paint `<head>` script writing to `<html>` attributes, with CSS or `useLayoutEffect` deriving presentation. Same recipe drives the theme-toggle thumb (Color & Theme).
  - **In-place reading nav (`CaseToc`, added 2026-06-04):** a horizontal frosted pill at the bottom of the viewspace — same fixed-bottom slot as `ViewSwitcher`, mutually exclusive via `ViewContext.detail` (only one renders at a time). Five sliding-thumb segments for the standardised `## The X` sections — Overview / Problem / Design / Outcome / Reflection — hardcoded (S10 heading standardisation guarantees the shape across all case studies). Click smooth-scrolls to the matching heading via **`scrollIntoView({ behavior: 'smooth' })`** — deliberately **not** URL hash navigation, which would collide with the case-study `/#slug` routing and accidentally close the detail. Active section is the last `<h2>` whose top crossed the **120px** trigger line from viewport top; a **bottom-of-page shortcut** promotes the last section when the document runs out of scroll (without it, geometrically the final heading never reaches the trigger and the thumb parks on the second-to-last section). Thumb mechanic mirrors `ViewSwitcher` exactly — `grid-cols-5`, thumb width `calc((100% - 8px) / 5)` so it equals one segment's inner width and `translateX(activeIndex * 100%)` snaps segment-to-segment. **Back-to-top** button (icon-only, frosted, sized `h-10 w-10 rounded-lg` to match the bar height + outer corner) lives as a sibling tucked behind the bar's right edge — initial `-translate-x-12 opacity-0` overlaps it with the bar (invisible because opacity is zero); past the **400px** scroll threshold it animates to `translate-x-0 opacity-100`, sliding into its rest position to the right of the bar. Marijana homepage pattern (BTT that emerges from her nav). Hidden below `lg` (`lg:flex`-only on the wrapper; mobile pass deferred with the rest of the mobile re-jig).
  - **Scrollspy settle = `scrollend` + fallback timer (2026-06-04, reusable pattern).** Without a settle signal, a TOC click causes scrollspy to visibly chew through every intermediate section as the smooth-scroll passes them, and — worse — promotes the second-to-last section one tick before the bottom-of-page shortcut can fire. Fix: on click, activeId commits to the user's target immediately (the thumb moves before the page does); a `navLockRef` flag suppresses scroll-driven activeId updates while in flight. The flag clears on the **`scrollend`** event (canonical signal, widely supported since 2023 — Chrome/Firefox; Safari 17.4+ as of March 2024); a **2000ms fallback timer** covers older Safari and scrolls the user interrupts mid-flight by manually scrolling (where `scrollend` may not fire). Both unlock paths call the same function; double-fire is harmless. General pattern: when an interaction has explicit intent and triggers a smooth animation/scroll the user didn't trigger, **set authoritative state on intent, then lock derived/observed state until the animation genuinely settles** — don't let mid-animation observations second-guess the user.
  - **⚠️ SEO tradeoff (open):** the modal kept *every* case-study body in the static HTML (crawlable). In-place renders only the **active** detail (hash-opened client-side), so case-study **text is no longer in the SSR output**. Open option: render all bodies into a hidden static block. *Undecided.*
  - Content authored as MDX (`src/content`, `lib/content.ts`). `ProjectsSection` (server) loads + pre-renders all panes (so a body is ready the instant its hash opens); `ProjectsExplorer` (client) holds the grid + detail + hash wiring.
- **Watch for ("flex children blockify") — 2026-06-03.** When dropping `items-center` (or any non-stretch `align-items`) from a flex parent, audit `inline-flex` / `inline-block` / `inline-*` children for unexpected stretching. The CSS spec **blockifies inline-level display values on flex/grid items** (`display: inline-flex` → `display: flex` at layout time), so the "inline" no longer protects from `align-items: stretch` (the flex default). Either add **`self-start`** (or `self-center` / `self-end`) on each child, OR keep an explicit `items-*` on the parent. Children with `w-full max-w-*` (e.g. the bio block in `Contact.tsx`) are **accidentally immune** because the max-width caps the stretch — a useful belt-and-suspenders pattern when a child should never exceed a known width. Bit us once on the Contact email CTA (stretched 140px → 576px when `items-center` came off the column) and silently on the channels row (invisible because content is short).

## Motion & Transitions
- **Grid → detail = in-place swap (2026-05-26; replaced the modal container-transform).** Opening a project replaces the cards grid with the detail view in the same column; the detail enters with **`.view-enter`** — a gentle **fade + 8px rise** (`@keyframes view-in`, `320ms`, `var(--ease-house)`), **skipped under `prefers-reduced-motion`**. No shared-element/grow morph (that was the modal's; deliberately not recreated — this shows the destination layout directly). Returning to the grid is immediate (no exit animation), with focus restored to the source card.
- **`--ease-house: cubic-bezier(0.65, 0, 0.35, 1)`** (added 2026-06-02) — the symmetric in-out "house" curve. Used by `.view-enter`; documents intent ("smooth in-out, neither direction noticeably picks up speed" from S3). Switcher thumb deliberately uses `ease-out` instead (snappy slide ≠ scene change). Durations stay context-specific.
  - *(Removed with the modal: the WAAPI box-morph, the grid erase/return fade, the `dialog::backdrop` dim+blur, the 360/300ms easing, the scroll-lock, and `scrollbar-gutter: stable`.)*
- **Case-study image sizing (`.case-body`, 2026-05-26):** lone breakout images are bounded by **height** (`--shot-max-h`, default `min(36rem,75vh)`) as well as width, so tall portraits (phone screens) scale down + center instead of stretching huge; wide landscapes still fill the column. Scoped to `> p:has(img) > img` (the 2-up grid, `<Figure>`, `<Compare>` are unaffected). Image→caption gap is **8px**, owned internally by `<figcaption>` inside `<figure>` (see `<Figure>` props above) — replaces the old sibling `*italic*` paragraph pattern, which margin-collapsed with the wrapper.
- **Card edge — clean elevation (decided 2026-05-22, ref: marijanapav.com/work):** cards have **no border** and **no big shadow**. Edge + lift come from a **two-layer `box-shadow` on `.project-card`** (in `globals.css`, not Tailwind — its arbitrary-shadow parser mangles multi-layer + alpha): a **4px ring** in `var(--card-ring)` (now **tracks `--background`** — see Color; reads as a soft halo/surface step) **+** a micro `0 1px 2px` dark shadow (`--foreground` @ 8%) for a whisper of lift. Cards also carry an explicit `bg-nav-fill` so they read as raised surfaces on the warm field. **NB:** the 4px ring sits on top of the 2px lift shadow, so the look is a clean framed tile, near-flat.
  - **Card-local hover/focus only (grid-spotlight retired 2026-06-04):** the active card itself reacts — **`outline-2 outline-offset-2 outline-accent`** on hover, **`motion-safe:hover:scale-[1.02]`** lift, title color → accent (and the eyebrow stays muted). Keyboard focus uses the same outline via the `focus-ring` utility. **The grid-spotlight system was removed in full** — *both* halves: the pointer-gated hover dim (`opacity:.6` on `:not(:hover)` siblings) AND the keyboard-focus blur+dim. Reasoning: the focused card already has a strong indicator on itself (outline + title shift); dimming the whole field on every hover was the heaviest visual change in the grid and made browsing feel restless. The accent outline + title shift is enough affordance; the dim+blur was redundant.

### Favicon — regenerate on accent change (2026-06-03 convention)
- **The favicon (`src/app/icon.png`) does not auto-track `--accent`.** It's a flat raster shipped to the browser; CSS doesn't touch it. The on-page logo *does* auto-track (CSS-masked alpha + `bg-accent`), which is why a stale favicon is easy to miss — caught 2026-06-03, after the accent had cycled `#9F106B` → `#140C34` → `#FF6440` → `#FB370A` and the favicon was still the original magenta.
- **Procedure when `--accent` changes:** regenerate the favicon by stitching the **alpha channel of `public/portfolio-logo.png`** (the canonical mask, 384×320) with the new accent RGB:
  ```bash
  node -e "
  const sharp=require('sharp'); const HEX='#FB370A'; // ← new accent
  (async()=>{
    const m=await sharp('public/portfolio-logo.png').metadata();
    const a=await sharp('public/portfolio-logo.png').extractChannel('alpha').raw().toBuffer();
    const rgb=await sharp({create:{width:m.width,height:m.height,channels:3,background:HEX}}).raw().toBuffer();
    const out=Buffer.alloc(m.width*m.height*4);
    for(let p=0,i=0,j=0;p<m.width*m.height;p++,i+=3,j+=4){out[j]=rgb[i];out[j+1]=rgb[i+1];out[j+2]=rgb[i+2];out[j+3]=a[p];}
    await sharp(out,{raw:{width:m.width,height:m.height,channels:4}}).png().toFile('src/app/icon.png');
  })();"
  ```
- **Cache note:** browsers cache favicons hard. After regeneration: `rm -rf .next/cache && npm run dev`, then hard-refresh the tab (Cmd+Shift+R) or close + reopen it. Production deploys cache-bust via Next's build hash on the icon route.
- **Why not auto-generate on build?** Possible (e.g. a `prebuild` script reading `--accent` from `globals.css`), but the accent doesn't change often and the script is short — manual regen is fine until it isn't.

## Spacing
- **All spacing follows an 8px grid** — margins, padding, *and* gaps use 8 / 16 / 24 / 32 … (Tailwind `-2` / `-4` / `-6` / `-8`), **not** in-between values like 12px (`-3`), 20px (`-5`), 4px (`-1`), or 2px (`-0.5`) — unless there's a specific reason. Keeps rhythm consistent across the UI.
- **Nav panel section rhythm = 48px (`mt-12`), decided 2026-05-23.** The standard gap **between navbar sections** (identity block → accent rule → menu → accent rule → readout, and top-of-column → logo) is **48px**. **Exception:** the logo + hero text are **one** "identity" section, so they're only **16px** (`mt-4`) apart internally. (48px is still a multiple of 8, so the 8px grid holds.)

## Shape & Radius
- **Standard border radius is 8px.** Use `rounded-lg` (Tailwind = `0.5rem` = 8px) for all UI elements — cards, inputs, containers, buttons.
- **Exception:** the decorative `.accent-fill` marker highlight uses intentionally *uneven* em-based radii (a hand-drawn highlighter look), so it doesn't follow the 8px rule.
