# Design Decisions

Project-wide design decisions for the portfolio. This documents *what* we decided and *why*, so choices stay consistent across sessions. Update it whenever a decision is made or changed.

---

## Stack & Architecture
- **Next.js 16 (App Router) + React 19 + TypeScript.** Deploy target is Vercel.
- **Static-first.** Every route is prerendered (static or SSG via `generateStaticParams`). No runtime data fetching for now. `dynamicParams = false` so unknown slugs 404 at build time.
- **Views are real routes (2026-05-27).** Under an `app/(site)/` route group sharing one chrome layout (nav/hero panel + fixed bottom switcher): `/` (projects), `/contact`, `/product-ideas`. Each prerenders its own view, so refresh/deep-link lands on the right view with **no client-side flash** — the active view *is* the pathname (`usePathname`), not React state. (Replaced the earlier single-page `ViewContext.active` model; that flashed the default view on refresh because one static HTML served every view.) `ViewContext` now only holds small cross-tree UI state (`detail` — the open project slug). The project **detail** still opens in-place on `/` via the `#slug` hash. *(`node` — the hovered/focused card coordinate — was removed 2026-06-02 alongside the Matrix readout.)*
- **Tailwind CSS v4.** Config lives in CSS (`@theme` in `globals.css`), not a `tailwind.config.js`. Plugins are loaded via `@plugin` in CSS.
- **Build note:** `next build` uses Turbopack by default in v16, regardless of the dev `--no-turbopack` flag.

## Content Pipeline (Writing)
- **MDX via `next-mdx-remote/rsc`** (chosen over `@next/mdx` page files) so we get a *content collection*: list pages by reading the filesystem, with frontmatter.
- Content lives in `src/content/{work,writing}/*.mdx`. One file = one entry.
- **Product ideas = typed data, not MDX (2026-05-27).** An idea is just a cover image + a one-line caption (no body), so the set is a typed `Idea[]` in **`src/content/ideas.ts`** (with `getIdeas()`), sitting beside the MDX sections rather than being a third MDX section. Fields mirror `Frontmatter` (`image`, `width`/`height`, `blurDataURL`, `caption`, `draft`) so promotion to MDX would be mechanical — the file header documents that path, and `lib/content.ts`'s `Section` type carries a pointer comment explaining why ideas isn't a `Section`.
- **Frontmatter** parsed with `gray-matter` (`src/lib/content.ts`): `title`, `summary`, `date` (ISO), optional `tags`, `role` (work), **`image`** (card cover, path under `/public`, e.g. `/work/footy/cover.png`), `draft`, `featured`.
- **Card blurb = `blurb`; `summary` = SEO (2026-05-24).** Two separate fields: **`blurb`** is the card preview text (clamped to 2 lines), falling back to `makeExcerpt(body)` (first sentences of the body) only when a file omits it. **`summary`** is kept distinct and reserved for the eventual SEO / OG meta description — it does *not* drive the card. (Authored blurb beats auto-extraction.)
- **Card cover (`image:`, wired 2026-05-23):** rendered via `next/image` (`fill`/`object-cover`) in a fixed **`h-[var(--card-cover-h)]`** card header (`--card-cover-h: 12.5rem` = 200px; tokenized 2026-06-02 — was hardcoded `h-[200px]`. S5: "tuned so ~4 cards show on screen"); falls back to a **`bg-image-placeholder`** block (a field-tracking shade — see Color) when unset. (Replaced the old index-keyed `TEMP_CARD_IMAGES` hack.) **Prefer landscape covers** — portrait phone screens get cropped to a thin band by `object-cover`.
- **Body images (`![]()`):** mapped in `mdx-components.tsx` to a styled **native `<img>`** (`my-8 w-full border border-border`, `loading="lazy"`, square corners) — *not* `next/image`, because MDX images have arbitrary unknown dimensions. Since these are raw `<img>`, **the format shipped is the format downloaded** (no on-the-fly conversion) — so the WebP/sizing decisions below matter most here.
- **`<Figure>` (centered, width-capped image; added 2026-05-23):** a custom MDX component for shots that shouldn't run the full column width. `<Figure src alt width="69%" />` — `width` is any CSS length/% (default `66%`), always centered (`mx-auto`), capped to the column (`maxWidth:100%`), same border/lazy as `img`. Use plain markdown `![]()` for full-width (default); reach for `<Figure>` to inset. **Because all body images render at the column width, on-screen *height* is governed by aspect ratio** — to match two images' heights, match their aspect ratios (or cap the squarer one's width: a 1:1 image at `width = 1/AR` of a landscape image renders the same height). The Act 2 colours (square) + typography (1.45:1) are a centered pair, both `width="69%"`.

### Image workflow — masters & derivatives (convention, 2026-05-23)
**Two-tier model. Never edit-over or ship a master; always regenerate derivatives from it.**
- **Masters** = full-res, *lossless* originals (PNG / the original drop). Live in **`/sources/<...mirror of /public path>`** (e.g. `sources/work/footy/colours.png`), **gitignored** (heavy, not deployed). When the user drops a raw file in the project root, **`mv` it into `/sources`** — *never* `rm` it (deleting masters = losing the ability to re-crop/resize; this bit us once — the 4 hand-dropped Footy images were deleted before the convention existed and need re-dropping).
- **Derivatives** = downscaled, web-format copies in **`/public/work/<slug>/`**, regenerated from the master via `sharp`. These are what the MDX references and what ships.
- **Sizing (the dominant size lever, ~free quality-wise):** resize so the longest edge ≤ **1600px** for landscape/full-width shots, or to **~2× the on-screen display width** for anything inset/gridded (e.g. the 2-up phone screens render ~352px → re-cut at **740px wide**). Most of the savings is right-sizing, not compression.
- **Format / compression (per image *type*):**
  - **Flat UI / screenshots / text** (palettes, component sheets, specs): **near-lossless** WebP (`{nearLossless:true, quality:80, effort:6}`) or lossless — pixel-clean text, and still tiny (these compress so well that even lossless often beats the PNG master).
  - **Photographic** (photos, mockups, moodboards): **lossy** WebP `quality:80–85` — lossless would balloon these.
  - WebP is universal in 2026; AVIF is an option for even smaller photographic files (slower encode). `effort:6` is a free quality-per-byte win.
- **Result so far:** the Footy set went **10 MB → ~0.7 MB (−93%)** at q80; UI shots later re-encoded near-lossless cost only a few dozen KB more each.
- **Real case studies** authored from a Notion export. The raw export lives in `/the-notion` (gitignored — heavy, has videos); curated + renamed masters live in `/sources/work/<slug>/`, derivatives in `/public/work/<slug>/`. Convert: demote Notion `#` headers to `##`, drop the leading title (the detail-view header shows it), strip videos (v1 decision: no video), keep image captions as `*italic*` lines.
- **Idea covers (2026-05-27):** same masters (`/sources/ideas/`) → derivatives (`/public/ideas/`) model. Each `Idea` carries a base64 **`blurDataURL`** (a tiny `sharp` LQIP) for `next/image` `placeholder="blur"`, plus intrinsic `width`/`height`. `scripts/cover-4x3.mjs` turns any source into a 4:3 **blurred-fill** (full image centered over a blurred copy of itself — fills the frame with no crop or letterbox) — though the launch covers were ultimately re-exported at a uniform **~1.55:1 (2000×1293)** instead. **Cache-bust gotcha:** swapping a cover at the *same* `/public` path serves a stale result (the browser **and** `.next/cache/images` key on the URL, not the bytes) — rename to a fresh filename (we version `-v2/-v3/…`) whenever a cover's content changes.
- **Idea carousel is a single non-scrolling page:** the cover is **height-capped** (`lg:max-h-[calc(100dvh-22rem)]`, `w-auto`) so on short viewports it scales *down* (staying centered, no crop/letterbox — the frame equals the image) instead of forcing the page to scroll. The `22rem` is the reserved budget for header + counter + caption + gaps.
- `draft: true` hides from listings; `featured: true` is reserved for a homepage rail. Lists sort newest-first by `date`.
- MDX plugins: `remark-gfm` (tables, etc.) + `rehype-slug` (heading anchors). Add `rehype-pretty-code` later if code samples need highlighting.
- Custom MDX element overrides in `src/components/mdx-components.tsx` (e.g. internal links routed through `next/link`).
- **Watch for ("where MDX breaks"):** a malformed expression or bad import inside any `.mdx` fails the whole build; frontmatter typos surface as missing fields, not errors.

## Responsiveness
- **Mobile-first.** Style the base (smallest) case unprefixed, then add `sm:`/`lg:` to scale *up*. Targets every device from phone to large desktop.
- **Fluid sizing (preferred while iterating):** size type *and* spacing with `clamp(min, vw, max)` so one value scales smoothly across all screens — no `sm:`/`lg:` variants to maintain or accidentally wipe when tweaking an element. e.g. heading `text-[clamp(1.25rem,4vw,1.5rem)]`, section `py-[clamp(3rem,8vw,5rem)]`. Keep `text-balance` on headings, `text-pretty` on leads. Values are rem-based so user zoom is respected. Adjusting size = nudge the `max` (one number).
- **Breakpoints** (Tailwind defaults — `sm 640 · md 768 · lg 1024 · xl 1280`) are reserved for true *layout* changes (column count, show/hide, grid → stack), **not** type/spacing scaling. See [[responsive-iteration-style]].
- **Overflow guards (convention):** flex children holding text get `min-w-0`; long unbroken strings get `break-words`.
- **Full-height (when needed):** use `min-h-dvh`, not `vh`/`min-h-screen`, to account for mobile browser chrome.
- **Deferred until content exists:** `next/image` with `sizes` + aspect ratios; ≥44px touch targets for interactive elements; `prefers-reduced-motion` guards for any animation.

## Layout & Structure
- **Single page** (`/`), **two-column on desktop — viewspace + navbar (decided 2026-05-26; replaced the 3-track gutter model):** a **full-width** CSS grid — `lg:grid-cols-[minmax(0,1fr)_var(--nav-w)]` (mobile: `grid-cols-1`, `px-6`, `gap-y-12`; desktop: `lg:px-0`, `gap-x-8` = 32px column gap, `lg:min-h-dvh`).
  - **Track 1 (`minmax(0,1fr)`) = the viewspace** — fills all width that isn't the navbar. Its content (cards / carousel / detail) is capped to **`--content-w` (49rem)** and **centered** (`mx-auto`), so the cards stay a constant readable width at every screen size and surplus width becomes balanced margin, not oversized cards. **This retired the parked wide-screen debt** (the old model let the cards flex-grow indefinitely).
  - **Track 2 (`var(--nav-w)`, 21rem) = the identity / nav panel** — fixed, dial-able width. As the *last* track of an edge-to-edge grid, its `bg-nav-fill` (white) **bleeds to the right viewport edge on its own**.
  - **Placement:** cards `<section>` `lg:col-start-1 lg:row-start-1`; panel `<aside>` `lg:col-start-2 lg:row-start-1`. The aside is **first in DOM** so it stacks on top on mobile (pin both to `lg:row-start-1` or the DOM-first aside pushes cards to row 2).
  - **Centered ≠ viewport-centered:** the cards center within the *viewspace* (viewport minus navbar), so the block sits slightly left of true page center — which counterbalances the navbar's weight on the right.
  - **Panel full-height:** `lg:min-h-dvh` on the grid + `lg:-mt-8 lg:-mb-24` on the aside (cancel the grid's `pt-8`/`pb-24`) so the white reaches the top & bottom screen edges.
  - **Scrollbars hidden site-wide (2026-05-26):** `* { scrollbar-width: none }` + `*::-webkit-scrollbar { display:none }` (scrolling still works). This was the settled answer to "the scrollbar sits on the navbar" — chosen over a fixed-navbar/scrolling-viewspace split (tried, reverted) and a recolored gutter. `scrollbar-gutter` dropped; `html { background: var(--background) }` (overscroll color).
  - **History:** this replaced the 2026-05-23 three-track model (`[1fr · minmax(0,49rem) · minmax(24rem,1fr)]` with a left-margin gutter track), which itself replaced a fixed-`18rem` + faked-`::after`-bleed model. Each step removed magic numbers; the 2-col + centered-cap is the simplest and fixes wide screens.
  - **Nav content wrapper:** the panel's content lives in an inner **`lg:sticky lg:top-8`** wrapper, **capped `lg:max-w-[28rem]`, `lg:mx-auto`** (centered in the panel), with **`lg:px-8`** (32px) gutters. The cap engages only once the panel exceeds cap+gutters; below that the content stays 32px off both edges. (Earlier the content was uncapped 32px-off-edges and got too wide on big screens.) Order top→bottom: logo row → hero text → accent rule → menu → accent rule → **(viewport tail)** → theme toggle. The toggle is **centered in the remaining tail** below the menu, not glued 48px under the lower accent rule — on `lg`, the sticky wrapper is `flex h-[calc(100dvh-2rem)] flex-col`, the upper block (logo+hero+menu) sits at natural height, and a `flex-1 items-center justify-center` lower block fills the remaining viewport height and centers the toggle in it. Mobile keeps natural `mt-12` stacking (mobile re-jig deferred). **Concession:** on very short viewports where the upper content grows tall, the lower block can be crushed — current content has headroom; revisit if menu/hero balloons.
  - **Hero text:** heading + subhead **merged into one left-aligned `<h1>`**, `text-sm` (14px), `lowercase` (CSS — source keeps real caps), `text-pretty`. Copy: "hello, i'm chukwuka, a systems-oriented **designer** … (sometimes)." ("designer" in `text-accent`.)
  - **Accent rules:** two **4px** lines (`h-1 bg-accent`) bracket the menu (one above, one below). They span the **full panel width** via `lg:-mx-8` (cancel the content `px-8`) while items stay inset 32px. (Replaced the old vertical divider + the two `border-accent` bracketing rules.)
  - **Matrix readout (retired 2026-06-02):** *Was* a mono coordinate gag `matrix node [row,col]` reflecting the hovered/focused card (idle `[–,–]`; coord in accent), wired via `node`/`setNode` on `ViewContext` + per-card hover/focus handlers. Removed in S9 — component, context fields, and the `COLS = 2` constant all deleted. The "chukwuka's matrix" brand name stays (it's the logo, unrelated). The tail slot is now the **theme toggle**. *(Earlier-removed: a mono "system readout" — status/location/live Lagos time. Showing the visitor's location/local time was discussed — timezone-client vs Vercel-edge vs IP-API — and **deferred** (privacy + static-build tradeoffs).)*
  - **Below `lg`** the grid collapses to one column: identity panel on top (full-width, no bleed), cards below.
  - **Why right-side nav:** chosen look; unconventional (nav usually top/left) and the split necessarily stacks on mobile.
- **Card-column routing (decided 2026-05-22):** the cards column is a swappable content area driven by **one shared piece of state** — `active: ViewId` in a **`ViewProvider` context** (`useView`). `ViewId = "projects" | "product-ideas" | "contact"`. Two controls set it (they live in different parts of the tree, hence the context):

Each item is a `view` (in-app route → `setActive`) or an `href` (external, new tab). *design* → `projects` (in-app); *contact* → `contact` (in-app); *essays* → `https://thechukwukaosakwe.wordpress.com/`; *newsletter* → `https://chukwukaosakwe.substack.com/`. (NavMenu still supports an inert third state for any item with neither.)
    - **Active state — `view` vs `activeFor` (decided 2026-05-22):** an item's *click target* (`view`) is separate from the *set of views it's highlighted for* (`activeFor`, defaults to `[view]`). *design* is a top-level route covering the whole design area, so `activeFor: ["projects", "product-ideas"]` — it stays active (accent + `aria-current`) whether you're on projects **or** product-ideas, and only drops on contact. Clicking it still lands on `projects` (the default sub-view); the switcher handles projects↔product-ideas within design.
    - **Styling (reworked 2026-05-23):** a **separated stack of flat outlined buttons** — each a full-width (equal), `rounded-lg`, `border-border` button, **no shadow** (white-on-white drop shadows read as noise), **left-aligned** `text-base`/`font-semibold`, `px-4 py-3`, `gap-2` (8px) between them. The menu **label** is "**some things i do**" in **Nico Moji** (matches the "chukwuka's matrix" logo), 18px, normal weight. (Explored on the way: full-width frosted bars → content-sized chips → a grouped `divide-y` list — settled on separated buttons; chips read as scattered, the `divide-y` list read as a table.)
    - **States:** **hover** fills the row (`hover:bg-foreground/5`) and warms text to accent; **active route** = `bg-accent-fill` (text `foreground`); **keyboard focus** = `focus-visible:border-accent`. (bg lives in the `INACTIVE`/`ACTIVE` state constants, not the base class, to avoid a Tailwind `bg-*` conflict between inactive white and active accent-fill.)
  - **`ViewSwitcher`** (client) = a **sub-toggle within the design area only** (projects ↔ product-ideas). Fixed, frosted segmented control docked bottom-center of the cards column (`fixed inset-x-0 bottom-6`, mirroring the page grid; `pointer-events-none` wrapper, only the pill interactive). `rounded-lg` track, two equal `grid-cols-2` segments, an absolutely-positioned **sliding thumb** (`bg-switcher-thumb` — its own stronger fill, *not* `--accent-fill`; `rounded-md`, `translateX(activeIndex*100%)`, `motion-safe`). **Both segment labels are the same** (`text-foreground`, same weight) — the thumb is the *sole* active indicator (backed by `aria-pressed`). **Renders `null`** when `active` isn't one of its two segments (e.g. contact) **or while a project detail is open** (the cards aren't rendered then — see `detail` in `ViewContext`).
  - **`CardsColumn`** (client) reads the context and renders the route: server `<ProjectsSection/>` (passed as a prop) for `projects`, `<ProductIdeas/>` for `product-ideas`, `<Contact/>` for `contact`. Default `"projects"` ⇒ the static build ships the projects grid; other routes mount client-side on toggle. *(Note: case-study bodies are no longer all in the static HTML — see Projects → in-place.)*
  - **`ProductIdeas`** (client) carousel: one **cover-fit** image at a time (`aspect-[4/3]`, framed with `.project-card`), one-line caption below, **looping** prev/next chevron handles flanking it, and a position counter pill **overlaid** bottom-right. Pushed down with `mt-[12vh]` to leave headroom for intro text. **TEMP:** reuses the 6 `public/` images + placeholder captions (`TEMP_IDEAS`) until a real product-ideas set exists.
  - **`Contact`** (`contact` route, styled 2026-05-23): centered column (`mt-[12vh]`, matching the carousel's offset). Keeps the accent hero line **"better call chuka!"**, a muted warmth sentence below, then a **primary `email me` CTA** (`mailto:` — the site's **one solid-accent button**; accent fill, `text-nav-fill`, arrow glyph, focus ring), and **github · farcaster** as understated text-links (the "read more" pattern: `text-text-muted` → accent on hover *and* focus). (User declined a contact form — no backend.)
  - **Adding a route:** add a `ViewId`, build its view component, branch in `CardsColumn`, and point a `NavMenu` item's `view` at it.
  - **Essays sourcing — deferred (discussed 2026-05-22).** Currently *essays* is just an external `href` to the WordPress site. We discussed bringing essays *into* the viewspace as an `essays` route, and what native publishing would cost. Findings:
    - **Headless WordPress is viable with zero WP-side changes:** the WordPress.com **public** REST API returns published posts — `https://public-api.wordpress.com/wp/v2/sites/thechukwukaosakwe.wordpress.com/posts` (verified 200; returns `title`, `content` HTML, `excerpt`, `date`, `link`, `jetpack_featured_media_url`). Clicking a card **opens its full case study IN PLACE** — the grid is swapped for the detail *within the same viewspace column*, so the navbar stays put.

Enter motion = **`.view-enter`** (fade + 8px rise, reduced-motion-safe). No shared-element/grow animation.

The whole `<dialog>` + WAAPI container-transform + scroll-lock + `::backdrop` apparatus was deleted.

In-place renders only the **active** detail (hash-opened client-side), so case-study **text is no longer in the SSR output**. Open option: render all bodies into a hidden static block. *Undecided.*

## Motion & Transitions
- **Grid → detail = in-place swap (2026-05-26; replaced the modal container-transform).** Opening a project replaces the cards grid with the detail view in the same column; the detail enters with **`.view-enter`** — a gentle **fade + 8px rise** (`@keyframes view-in`, `320ms`, `var(--ease-house)`), **skipped under `prefers-reduced-motion`**. No shared-element/grow morph (that was the modal's; deliberately not recreated — this shows the destination layout directly). Returning to the grid is immediate (no exit animation), with focus restored to the source card.
- **`--ease-house: cubic-bezier(0.65, 0, 0.35, 1)`** (added 2026-06-02) — the symmetric in-out "house" curve. Used by `.view-enter`; documents intent ("smooth in-out, neither direction noticeably picks up speed" from S3). Switcher thumb deliberately uses `ease-out` instead (snappy slide ≠ scene change). Durations stay context-specific.
  - *(Removed with the modal: the WAAPI box-morph, the grid erase/return fade, the `dialog::backdrop` dim+blur, the 360/300ms easing, the scroll-lock, and `scrollbar-gutter: stable`.)*
- **Case-study image sizing (`.case-body`, 2026-05-26):** lone breakout images are bounded by **height** (`--shot-max-h`, default `min(36rem,75vh)`) as well as width, so tall portraits (phone screens) scale down + center instead of stretching huge; wide landscapes still fill the column. Scoped to `> p:has(img) > img` (the 2-up grid, `<Figure>`, `<Compare>` are unaffected). Image→italic-caption gap tightened to **8px**.
- **Card edge — clean elevation (decided 2026-05-22, ref: marijanapav.com/work):** cards have **no border** and **no big shadow**. Edge + lift come from a **two-layer `box-shadow` on `.project-card`** (in `globals.css`, not Tailwind — its arbitrary-shadow parser mangles multi-layer + alpha): a **4px ring** in `var(--card-ring)` (now **tracks `--background`** — see Color; reads as a soft halo/surface step) **+** a micro `0 1px 2px` dark shadow (`--foreground` @ 8%) for a whisper of lift. Cards also carry an explicit `bg-nav-fill` (white) so they read as raised surfaces on the warm field. **NB:** the 4px ring sits on top of the 2px lift shadow, so the look is a clean framed tile, near-flat.
  - **Hover/focus spotlight (decided 2026-05-22; hover blur removed 2026-05-26):** **hover** now only **dims** the other cards (`opacity:.6`, `@media (hover:hover)`) — no blur. **Keyboard focus** still **blurs + dims** the others (`filter: blur(2px)` + `opacity:.6`, not pointer-gated, since keyboard users vary). The active card stays sharp; hover additionally lifts with `motion-safe:hover:scale-[1.02]`. Cards carry Tailwind `transition` so it eases.
  - **Focus-visible:** keyboard focus drives the spotlight above **and** marks the focused card with an accent `outline-2 outline-offset-2 outline-accent` (a distinct, unambiguous focus ring for a11y). `:focus-visible`, so mouse clicks — which open the modal — don't trigger it.

## Typography
- **Nata Sans** (body/sans, `next/font/google`) + **Geist Mono** (code). *(Note: Next has no fallback-metrics for Nata Sans yet — harmless dev warning, minor CLS risk.)*
- **Nico Moji** for the homepage greeting — self-hosted via `next/font/local` (`src/app/fonts/NicoMoji-Regular.ttf`, OFL-licensed; not on Google Fonts). Exposed as `--font-nico-moji`.
- Long-form bodies use `prose case-body max-w-none` (`@tailwindcss/typography`). **As of 2026-06-02, `prose-stone` and `dark:prose-invert` are dropped** — `.case-body` overrides the full `--tw-prose-*` palette to source from `--foreground` / `--accent` / `--text-muted` / `--border`. One source of truth; both modes flip automatically.
- Headings use `tracking-tight`; hero/title text uses `text-balance`, lead paragraphs `text-pretty`.

## Spacing
- **All spacing follows an 8px grid** — margins, padding, *and* gaps use 8 / 16 / 24 / 32 … (Tailwind `-2` / `-4` / `-6` / `-8`), **not** in-between values like 12px (`-3`), 20px (`-5`), 4px (`-1`), or 2px (`-0.5`) — unless there's a specific reason. Keeps rhythm consistent across the UI.
- **Nav panel section rhythm = 48px (`mt-12`), decided 2026-05-23.** The standard gap **between navbar sections** (identity block → accent rule → menu → accent rule → readout, and top-of-column → logo) is **48px**. **Exception:** the logo + hero text are **one** "identity" section, so they're only **16px** (`mt-4`) apart internally. (48px is still a multiple of 8, so the 8px grid holds.)

## Shape & Radius
- **Standard border radius is 8px.** Use `rounded-lg` (Tailwind = `0.5rem` = 8px) for all UI elements — cards, inputs, containers, buttons.
- **Exception:** the decorative `.accent-fill` marker highlight uses intentionally *uneven* em-based radii (a hand-drawn highlighter look), so it doesn't follow the 8px rule.
